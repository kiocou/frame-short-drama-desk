# 短剧下载神器原生桌面端重构设计

日期：2026-07-16

## 背景

项目是基于 Tkinter 与 ttkbootstrap 的 Windows 原生桌面下载工具。后台已具备搜索、分享链接识别、分集并发下载、FFmpeg 合并、任务持久化和本机配置能力。本次重构保留后台协议和运行方式，重建前端信息架构、视觉系统与状态反馈。

## 目标

- 搜索发现与粘贴下载在首页拥有同等优先级。
- 采用“清透影库”视觉方向：银灰背景、深绿主色、珊瑚强调色。
- 保持原生桌面架构，不引入浏览器内核或长期运行的动画线程。
- 让搜索、下载、合并和异常状态可快速扫描，并支持键盘常用操作。
- 修复影响任务连续性、状态准确性、数据恢复和内容访问的现有缺陷。

## 非目标

- 不修改短剧搜索来源、视频解析协议或 FFmpeg 媒体管线。
- 不改变 `config.json` 与 `desktop_tasks.json` 的现有字段含义。
- 不增加用户系统、云同步、主题市场或复杂插件机制。
- 不为了视觉效果引入 WebView、Electron 或持续高频绘制。

## 信息架构

应用使用固定侧边导航和单一内容工作区，共四个页面：

1. 首页：全网搜索与粘贴下载双入口、运行状态、今日统计和最近任务。
2. 搜索：关键词、来源、分类、页码筛选；结果列表、详情与下载操作。
3. 任务：批量输入、队列控制、任务进度、失败重试、链接复制和导出。
4. 设置：设备配置、平台选择、自动合并开关和配置状态。

首页只承担开始工作和查看状态。复杂筛选与批量操作进入独立页面，避免在同一工具栏堆叠所有控件。

## 视觉系统

- 背景：低饱和银灰绿；主要内容面使用白色。
- 主色：深绿，用于主操作、选中导航和有效进度。
- 强调色：珊瑚色，用于粘贴下载入口、失败提示和需要关注的状态。
- 文字：深墨绿主文本，灰绿色次级文本，保持清晰对比。
- 容器：使用细边界和分区，不使用大面积阴影、渐变或多层嵌套卡片。
- 字体：优先使用 Windows 自带的 Microsoft YaHei UI，避免额外字体依赖。
- 图标：使用轻量 Canvas 线性图标或系统可用符号，并提供悬停提示。

## 组件与职责

`desktop_app.py` 保留应用控制器职责：持有任务状态、启动后台工作、处理持久化并协调页面。

新建 `desktop_ui/` 包：

- `theme.py`：颜色、字体、间距和 ttk 样式。
- `motion.py`：基于 Tkinter `after` 的短时缓动与更新合并。
- `widgets.py`：侧边导航、状态徽标、输入区、提示条和空状态等复用控件。
- `pages/home.py`：双入口首页和最近任务。
- `pages/search.py`：搜索筛选与结果列表。
- `pages/tasks.py`：任务队列、进度与批量操作。
- `pages/settings.py`：本机配置。

页面只负责布局、输入收集和结果呈现，通过明确回调调用控制器。后台模块不依赖任何页面类型。

## 数据流与线程模型

数据流固定为：

`用户操作 -> 输入校验 -> 控制器 -> 后台线程/线程池 -> UI 事件队列 -> Tk 主线程更新 -> 持久化`

网络、解析、下载和合并在后台执行。所有 Tk 控件更新只在主线程中进行。任务模型由锁保护，高频进度事件合并后刷新，避免重复重建完整列表。

## 交互与动效

- 侧边导航切换使用约 160ms 的选中指示条移动和内容轻微位移。
- 首页模块首次出现分两段进入，总时长不超过 220ms。
- 进度值平滑追随真实状态，刷新频率受控，不使用持续装饰动画。
- 搜索和识别支持 Enter 键；按钮忙碌时禁用重复提交。
- 预期内错误显示在输入区或任务行内，并提供重试。
- 清空任务等破坏性操作继续使用确认弹窗。
- 状态同时使用文字与颜色表达，不依赖颜色作为唯一信息来源。

## 缺陷修复

### 合并状态无法结束

合并成功时将同系列任务的 `merge_status` 设置为“已合并”，`merge_progress` 设置为 100。最终渲染不能继续把该系列识别为“正在合并”。

### 运行中新增任务滞留

下载调度器不再只遍历启动时的任务快照。每轮从受锁保护的任务集合中领取“等待”任务；运行中新增的任务会被同一下载周期继续领取。失败任务不会自动无限重试，只能由明确重试操作恢复为“等待”。

### 宽表格内容不可访问

搜索页只保留标题、来源、分类、集数和操作等高频字段；完整 ID 与链接放入选中项详情区。任务页只保留剧集、状态、进度、结果与操作。窗口变窄时优先收缩描述列，关键信息保持可见。

### 损坏任务记录导致启动异常

加载任务文件时验证顶层必须为列表、每项必须为字典。异常数据会保留原文件、使用空任务列表启动，并在界面显示可读警告，不静默崩溃。

## 异常与空状态

- 无搜索结果：说明当前筛选无结果，并保留修改关键词的入口。
- 无下载任务：首页和任务页显示粘贴链接或前往搜索的操作。
- 搜索失败：显示来源和简化后的原因，可直接重试。
- 下载失败：任务行显示失败原因与重试操作，其他任务继续执行。
- 配置缺失：设置页与首页状态区提示，相关下载操作引导到设置页。

## 测试与验收

- 保持现有后端单元测试全部通过。
- 新增合并状态收口、运行中追加任务、失败任务不自动循环、损坏任务文件恢复测试。
- 新增页面创建烟雾测试，验证四个页面和关键控件可实例化。
- 实际启动桌面端检查 1280x780 与最小 1080x680 窗口，确保文字、按钮和列表不重叠。
- 搜索、识别和下载过程中窗口保持可拖动、可切换页面。
- 动效不创建额外常驻线程；列表与进度更新保持事件合并策略。
- 应用继续通过 `start.ps1` 启动，并可沿用现有 PyInstaller 打包配置。

## 完成标准

- 首页能从搜索和粘贴下载两条路径一步进入工作流。
- 搜索、任务、设置功能完整保留，主要动作无需横向滚动寻找。
- 合并完成后状态准确结束，运行中追加任务能够自动继续。
- 损坏的任务持久化数据不会阻止应用启动。
- 全部自动化测试通过，桌面端在目标尺寸下完成视觉与交互验收。
